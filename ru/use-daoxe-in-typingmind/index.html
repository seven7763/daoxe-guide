DaoXE в TypingMind

TypingMind — BYOK-фронтенд, работающий целиком в вашем браузере. Диалог Add Custom Model принимает любой OpenAI-совместимый эндпоинт — DaoXE в одном диалоге.

Обновлено 2026-07-20

TypingMind — это bring-your-own-key фронтенд: чаты, настройки и API-ключи живут в вашем браузере, а запросы идут прямо к названному провайдеру. Диалог Add Custom Model — универсальная OpenAI-совместимая поверхность, ровно форма DaoXE (гайд по дешёвым API).

Зачем направлять TypingMind через DaoXE#

  • Ключи не покидают браузер. Доки TypingMind прямо пишут: данные и ключи «хранятся локально в браузере и никогда не уходят на серверы TypingMind».
  • Работает и в веб-приложении, и в статической self-host сборке. Поток кастомных моделей одинаков — DaoXE заведётся даже на приватном деплое.
  • Контроль на модель. Длина контекста, плагины и vision задаются на каждую кастомную модель — вы решаете, что умеет каждая модель DaoXE.

Настройка в TypingMind#

  1. Откройте диалог. Иконка Models в левом сайдбаре → + Add Custom Model (справа сверху) — тот же поток, что в доках TypingMind для Ollama, LM Studio и LocalAI.
  2. Тип API. Выберите тип OpenAI (пример Gemini в доках показывает селектор API Type — для DaoXE нужен OpenAI-вариант).
  3. Вставьте полный эндпоинт. Endpoint: https://daoxe.com/v1/chat/completions. Все документированные примеры TypingMind несут полный путь (напр. http://localhost:1234/v1/chat/completions для LM Studio) — не голый base URL.
  4. ID модели, заголовки, Test. Введите точный ID модели из GET /v1/models, задайте длину контекста, добавьте строку кастомного заголовка (Authorization : Bearer sk-…) для ключа, затем нажмите Test — приложение проверит эндпоинт и способности до сохранения.

Что важно учесть

Endpoint — полный путь: каждый документированный пример кастомной модели заканчивается на /chat/completions; один base URL провалит шаг Test. ID моделей ручные: подтяжки списка моделей для кастомных моделей нет — копируйте точные ID из GET /v1/models, по модели на запись. Ключ в заголовках: доки ведут кастомные ключи через строку Custom Headers (их пример для Gemini использует apiKey); для OpenAI-совместимых эндпоинтов — Authorization: Bearer. Происхождение браузера имеет значение: запросы идут из вашего браузера прямо на эндпоинт, поэтому self-host TypingMind на http://localhost может упереться в CORS-стены, которых нет у хостед-приложения (https) — если Test проходит в одном и падает в другом, разница именно в этом. Test до сохранения: кнопка проверяет эндпоинт и детектирует способности; неверный ID или путь всплывут там, а не в чате. Больше клиентов — в заметки по настройке клиентов.

Убедитесь, что отдают настоящую модель#

Сначала проверьте эндпоинт, а не клиент — если это не работает, настройки не помогут:

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

Проверьте эндпоинт вне приложения, затем сравните сложный промпт с официальным API при temperature 0:

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

Проверяйте нас, а не верьте на слово

Направьте открытый бенчмарк на DaoXE и на официальный API и сравните при temperature 0. Затем изучите, как поймать подмену модели, чтобы дешёвый эндпоинт не подменил вам модель на меньшую.

Частые вопросы#

TypingMind работает с DaoXE?

Да — Models → Add Custom Model → тип OpenAI, endpoint https://daoxe.com/v1/chat/completions, ключ в кастомном заголовке.

Куда положить API-ключ?

В строку Custom Headers — Authorization : Bearer sk-ваш-ключ-daoxe. TypingMind документирует кастомные заголовки для своей кастомной модели Gemini; тип OpenAI читает те же заголовки.

Почему список моделей не заполняется сам?

Кастомные модели в TypingMind вводятся вручную — на страницах Ollama/LM Studio/LocalAI в доках ID модели нужно вписать. Копируйте точные ID из GET /v1/models.

Сколько стоит?

По моделям и аккаунту — актуальные цены; пополнение — фиксированные 1 ¥ = $1 квоты.
