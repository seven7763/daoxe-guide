DaoXE в goose

goose — локальный расширяемый open-source агент. Его провайдер OpenAI принимает любой совместимый эндпоинт: направьте его на DaoXE, и один ключ будет управлять планированием, правками и MCP tool calls через разных вендоров.

Обновлено 2026-07-20

goose говорит с любым OpenAI-совместимым эндпоинтом через провайдер OpenAI (или кастомный провайдер в goose configure), поэтому переход на DaoXE — смена base URL и ключа. Выгода — разделение ролей по-гусиному: планирование на топ-модели, тяжёлые tool-шаги на дешёвой, гайд по дешёвым API.

Зачем направлять goose через DaoXE#

  • Один ключ на весь каталог. Меняйте модель агента без отдельных аккаунтов — живой список в GET /v1/models.
  • Роли по цене. Дорогое рассуждение — на планирование, дешёвые модели — на повторяющиеся tool-шаги.
  • Расширения стоят токенов. Каждый MCP-сервер — это контекст в каждом ходе; с одним балансом это легко настраивать.

Настройка в goose#

  1. Откройте настройку провайдера. В goose Desktop — вкладка Models; в CLI — goose configure → Configure Providers.
  2. Выберите провайдер OpenAI. Вставьте ключ DaoXE; на вопрос о host / base path укажите https://daoxe.com/v1 — заканчивайте на /v1.
  3. Задайте модель. Введите точный ID из GET /v1/models — на кастомном хосте goose не угадает сам.
  4. Прогоните реальную задачу. Отправьте небольшую правку и смотрите tool calls — так проверяются и маршрутизация, и способности модели.
bash
# CLI: env-based setup for the OpenAI provider
cat >> ~/.config/goose/config/.env <<'EOF'
OPENAI_HOST=https://daoxe.com/v1
OPENAI_API_KEY=sk-you…-key
EOF
goose

Что важно учесть

Tool calling обязателен — goose всё делает через него, и его собственная документация исключает модели без вызова инструментов; берите модель с настоящим function calling. Нюанс кэша: маркеры cache_control goose добавляет автоматически только на провайдерах Anthropic, Bedrock, Databricks, OpenRouter и LiteLLM — на generic-пути OpenAI-compatible автоматического кэша нет, длинные сессии тарифицируются как обычный input. Base URL — до /v1; ID привязаны к аккаунту. Больше клиентов — в заметки по настройке клиентов.

Убедитесь, что отдают настоящую модель#

Сначала проверьте эндпоинт, а не клиент — если это не работает, настройки не помогут:

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

Эндпоинт формы OpenAI, который никогда не помечает кэш-брейкпоинты, — ровно тот случай, который надо проверить: докажите связность, затем сравните сложный промпт с официальным API при temperature 0:

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

Проверяйте нас, а не верьте на слово

Направьте открытый бенчмарк на DaoXE и на официальный API и сравните при temperature 0. Затем изучите, как поймать подмену модели, чтобы дешёвый эндпоинт не подменил вам модель на меньшую.

Частые вопросы#

goose работает с DaoXE?

Да — провайдер OpenAI в goose принимает кастомный host: https://daoxe.com/v1, ваш ключ и точный ID модели.

Почему сессия встаёт на tool calls?

Выбранная модель не умеет полноценный function calling. Возьмите tool-совместимую модель из GET /v1/models.

Есть ли кэш промптов для Claude через goose?

Нет, автоматически — маркеры кэша ставятся только на Anthropic/Bedrock/OpenRouter/LiteLLM-провайдерах goose, не на generic OpenAI-пути. Ожидайте тарификацию как обычного input.

Сколько это стоит?

По модели и аккаунту — см. актуальные цены; пополнение — фиксированные 1 ¥ = $1 квоты любым способом.
