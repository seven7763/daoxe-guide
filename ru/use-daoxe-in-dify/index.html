DaoXE в Dify

Dify — open-source платформа LLM-приложений: chatflow, workflow и агенты. Провайдер OpenAI-API-compatible принимает любой OpenAI-эндпоинт, поэтому один ключ DaoXE питает каждую модель во всех приложениях воркспейса.

Обновлено 2026-07-20

Dify берёт модели через плагины-провайдеры. Установите плагин OpenAI-API-compatible из Marketplace, добавьте модель как customizable model — и каждое приложение Dify (чат, workflow, агент) сможет вызывать ваш каталог DaoXE (гайд по дешёвым API). Модели объявляются по одной, поэтому настоящая настройка живёт в полях конкретной модели.

Зачем направлять Dify через DaoXE#

  • Приложения наследуют модель. Один провайдер на воркспейс обслуживает chatflow, workflow и Agent-ноды.
  • Переключатели способностей на модель. Context size, тип function-call и vision объявляются на каждую модель — приложения знают, что умеют.
  • Self-hosted или Cloud. И то и другое принимает один провайдер и один эндпоинт.

Настройка в Dify#

  1. Установите провайдера. Integrations → Model Provider (или Marketplace), установите OpenAI-API-compatible.
  2. Добавьте модель. На карточке провайдера нажмите Add Model. Model Name — точный ID из GET /v1/models; Model Type = LLM.
  3. API Base URL. Для LLM введите https://daoxe.com/v1. Для embedding/rerank — без /v1: плагин дописывает версию сам, полный URL даёт задвоенный путь.
  4. Поля способностей. API Key = ваш ключ DaoXE; Completion mode = Chat; Model context size = реальное окно модели; Upper bound for max tokens = разумный лимит; Function Call Type = Tool Call, если модель умеет; Vision Support — по модели.

Что важно учесть

Правило /v1 зависит от типа модели: в собственных доках плагина для LLM base URL заканчивается на /v1, а для embedding/rerank/STT/TTS указывается голый хост — эти пути дописываются внутри, и неверный выбор даёт задвоенный путь и 404. Function Call Type по умолчанию Not Support: оставите так — Agent-ноды никогда не вызовут инструменты; ставьте Tool Call (и поле стриминга tool-call) для моделей, которые это умеют. Context size по умолчанию 4096: окно заметно меньше реального молча обрезает длинные промпты. Агенту нужен нативный tool calling: в troubleshooting самих доков Dify сказано, что OpenAI-совместимым эндпоинтам часто не хватает полной поддержки инструментов — подбирайте модель соответственно. Token parameter name: часть новых моделей ждёт max_completion_tokens; если автодетект ошибся, задайте явно. Больше клиентов — в заметки по настройке клиентов.

Убедитесь, что отдают настоящую модель#

Сначала проверьте эндпоинт, а не клиент — если это не работает, настройки не помогут:

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

Проверьте провайдера одним приложением, прежде чем собирать workflow, затем сравните сложный промпт с официальным API при temperature 0:

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

Проверяйте нас, а не верьте на слово

Направьте открытый бенчмарк на DaoXE и на официальный API и сравните при temperature 0. Затем изучите, как поймать подмену модели, чтобы дешёвый эндпоинт не подменил вам модель на меньшую.

Частые вопросы#

Какого провайдера выбрать в Dify?

Установите плагин OpenAI-API-compatible и добавьте DaoXE как customizable model: точный ID, ключ и API Base URL.

Почему эндпоинт отдаёт 404 на embeddings?

Для embedding/rerank/STT/TTS плагин сам дописывает путь версии — указывайте голый хост (без /v1), а /v1 оставляйте только для LLM.

Почему агент не вызывает инструменты?

Function Call Type у записи модели по умолчанию Not Support — поставьте Tool Call и возьмите модель с настоящим function calling.

Сколько стоит?

По моделям и аккаунту — актуальные цены; пополнение — фиксированные 1 ¥ = $1 квоты.
