DaoXE в NextChat

NextChat (проект, известный раньше как ChatGPT-Next-Web) — self-hosted чат-UI, провайдер OpenAI в котором принимает кастомный эндпоинт. Направьте его на DaoXE — и один ключ наполнит его пикер вашим каталогом.

Обновлено 2026-07-20

NextChat говорит по OpenAI-совместимому HTTP, поэтому DaoXE — это замена эндпоинта: в UI настроек или через OPENAI_BASE_URL при self-host. Список CUSTOM_MODELS затем показывает ровно те ID аккаунта, что нужны (гайд по дешёвым API).

Зачем направлять NextChat через DaoXE#

  • Self-host за минуты. Docker и две env-переменные; переписка живёт на вашем сервере.
  • Пикер = ваш каталог. CUSTOM_MODELS включает (или через - скрывает) реальные ID из GET /v1/models.
  • Один ключ на инстанс. Все пользователи вашего NextChat делят баланс DaoXE.

Настройка в NextChat#

  1. Облачная версия: Settings. Settings → Model Provider → OpenAI: ключ DaoXE и API endpoint https://daoxe.com/v1.
  2. Self-hosted: env. OPENAI_API_KEY и OPENAI_BASE_URL=https://daoxe.com/v1 в docker-compose / Vercel.
  3. Настройте список. CUSTOM_MODELS — точные ID; недоступные встроенные скрывайте префиксом -.
  4. Тестовое сообщение. Затем сверьте поле model в ответе с выбранным ID.
bash
# self-hosted: docker-compose env
OPENAI_API_KEY=sk-you…-key
OPENAI_BASE_URL=https://daoxe.com/v1
CUSTOM_MODELS=glm-5.3-flash,-gpt-4o

Что важно учесть

OPENAI_BASE_URL — до /v1: NextChat сам добавит /chat/completions, а без суффикса получится классический 404. Встроенные имена, которых нет у вашего ключа, надо скрывать через CUSTOM_MODELS=-имя — иначе пикер предлагает мёртвые пункты. Server-side vs client-side режим решает, где живёт ключ — для общих развёртываний держите его на сервере. Больше клиентов — в заметки по настройке клиентов.

Убедитесь, что отдают настоящую модель#

Сначала проверьте эндпоинт, а не клиент — если это не работает, настройки не помогут:

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

Сначала проверьте эндпоинт без UI, затем сравните сложный промпт с официальным API при temperature 0:

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

Проверяйте нас, а не верьте на слово

Направьте открытый бенчмарк на DaoXE и на официальный API и сравните при temperature 0. Затем изучите, как поймать подмену модели, чтобы дешёвый эндпоинт не подменил вам модель на меньшую.

Частые вопросы#

NextChat работает с DaoXE?

Да — замена OpenAI-эндпоинта: ключ и https://daoxe.com/v1, в Settings или через OPENAI_BASE_URL.

Почему часть моделей в пикере ошибается?

Это встроенные имена, недоступные вашему ключу. Скройте их: CUSTOM_MODELS=-gpt-4o,…, оставив ID из GET /v1/models.

Self-host или Vercel?

Одни и те же env-переменные. В общем доступе держите ключ на сервере (API-режим), а не в браузерах посетителей.

Сколько стоит?

По моделям и аккаунту — актуальные цены; пополнение — фиксированные 1 ¥ = $1 квоты.
