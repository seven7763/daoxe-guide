DaoXE в Msty

Msty — десктоп-приложение, где локальные модели и удалённые API живут рядом. Его тип «Open AI Compatible» принимает любой OpenAI-совместимый эндпоинт — DaoXE встаёт одной записью провайдера.

Обновлено 2026-07-20

Msty гоняет локальные модели через встроенный сервис, а удалённых провайдеров — через один экран настроек. Нужный тип — Open AI Compatible: имя, API endpoint, ключ — и DaoXE ложится в эту форму один в один (гайд по дешёвым API).

Зачем направлять Msty через DaoXE#

  • Локальное и облако в одном пикере. Каталог DaoXE стоит в селекторе моделей рядом с оффлайн-моделями.
  • Workspaces изолируют ключи. Каждое рабочее пространство Msty хранит свои API-ключи — на общей машине можно держать по ключу DaoXE на команду.
  • Настройки на модель. Категории модели (Text / Embedding / Vision / Coding) и лишние JSON-параметры едут вместе с кастомным провайдером.

Настройка в Msty#

  1. Settings → Remote Model Providers. Откройте настройки из сайдбара и нажмите Remote Model Providers.
  2. Добавьте провайдера. Кнопка Add New Provider (справа сверху). В выпадающем списке Models Provider выберите Open AI Compatible — тот же путь, что в доках Msty для SambaNova.
  3. Имя, endpoint, ключ. Имя DaoXE; API endpoint https://daoxe.com/v1 (документированные примеры Msty всегда заканчиваются на /v1, напр. https://api.sambanova.ai/v1); вставьте ключ DaoXE.
  4. Добавьте модели. Сначала нажмите Fetch Models — если сработает, имена моделей подставятся сами. Иначе добавьте каждую модель вручную точным ID из GET /v1/models и нажмите Add.

Что важно учесть

Fetch Models — ворота: в доках Msty прямо сказано, что она «не может подтянуть их автоматически», если у провайдера нет рабочего /v1/models, — пустой пикер лечится ручным добавлением по точному ID. Endpoint сохраняет /v1: все документированные примеры Open AI Compatible заканчиваются версионным путём; голый хост даёт 404. Ключи живут в keychain: Msty хранит ключи на workspace в keychain устройства — импортированный workspace на другой машине выдаёт «Error while decrypting the ciphertext», пока ключи не введёте заново (или сознательно не сохраните без шифрования). Реестр ≠ ваш аккаунт: реестр моделей Msty отделён от записей провайдеров — обновление реестра не добавит модели DaoXE. Больше клиентов — в заметки по настройке клиентов.

Убедитесь, что отдают настоящую модель#

Сначала проверьте эндпоинт, а не клиент — если это не работает, настройки не помогут:

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

Проверьте эндпоинт вне приложения, затем сравните сложный промпт с официальным API при temperature 0:

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

Проверяйте нас, а не верьте на слово

Направьте открытый бенчмарк на DaoXE и на официальный API и сравните при temperature 0. Затем изучите, как поймать подмену модели, чтобы дешёвый эндпоинт не подменил вам модель на меньшую.

Частые вопросы#

Msty работает с DaoXE?

Да — Settings → Remote Model Providers → Add New Provider → Open AI Compatible, endpoint https://daoxe.com/v1 и ключ DaoXE.

Почему список моделей пуст?

Msty тянет модели из /v1/models провайдера; если запрос упал или вернул пустоту, пикер останется пустым. Добавьте модель вручную точным ID — это документированный фолбэк.

API endpoint включает /v1?

Да — документированные примеры Open AI Compatible в Msty заканчиваются на /v1 (напр. https://api.sambanova.ai/v1). Версионный путь сохраняйте.

Сколько стоит?

По моделям и аккаунту — актуальные цены; пополнение — фиксированные 1 ¥ = $1 квоты.
