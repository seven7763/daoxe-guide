DaoXE в SillyTavern

SillyTavern — фронтенд для опытных пользователей. Источник Custom (OpenAI-compatible) в Chat Completion принимает любой OpenAI-эндпоинт: один ключ DaoXE питает чаты с персонажами, групповые чаты и world-book сценарии всем каталогом аккаунта.

Обновлено 2026-07-20

SillyTavern подключается к шлюзам через Chat Completion → Custom (OpenAI-compatible): Custom Endpoint (Base URL), ключ и ID модели. Интерфейс сам предупреждает о двух классических ошибках — пропущенном /v1 и вручную дописанном /chat/completions — поэтому прочитайте настройку, прежде чем что-то вводить (гайд по дешёвым API).

Зачем направлять SillyTavern через DaoXE#

  • Сделан для глубокой кастомизации. Карточки персонажей, lorebook, instruct-шаблоны и групповые чаты — всё на одном эндпоинте.
  • Один ключ, много вендоров. Меняйте ID моделей между чатами, не трогая эндпоинт.
  • Прокси на сервере. Запросы ретранслирует Node-сервер — CORS не блокирует браузер.

Настройка в SillyTavern#

  1. Откройте API Connections. Иконка вилки сверху → API Connections. Выберите API = Chat Completion.
  2. Выберите источник Custom. Chat Completion Source = Custom (OpenAI-compatible).
  3. Эндпоинт и ключ. Custom Endpoint (Base URL): https://daoxe.com/v1 — без /chat/completions, SillyTavern добавит сам. Ключ DaoXE — в Custom API Key.
  4. Модель, Connect, тест. Введите точный ID из GET /v1/models в Enter a Model ID (или выберите из списка, если он заполнится), нажмите Connect, затем прогоните Test Message.

Что важно учесть

Правило /v1 работает в обе стороны: ST дописывает /chat/completions к введённому адресу — подсказка в UI буквально гласит «Не работает? Добавьте /v1 в конце!» и предупреждает, что суффикс добавится автоматически. Голый https://daoxe.com даёт 404; правильное значение заканчивается на /v1. Prompt post-processing: если чат падает с жалобами на роли/последовательность (некоторые OpenAI-серверы принимают только строго чередующиеся сообщения), настройте Custom Prompt Post-Processing — варианты Strict и Semi-strict перезаписывают историю. Tool calling: варианты «no tools» вырезают вызовы инструментов — берите вариант with-tools, если модель умеет function calling. Bypass API status check — для эндпоинтов, которые работают, но проваливают статус-пробу ST; попробуйте его, прежде чем переписывать URL. Точные ID из GET /v1/models; придуманные падают на первом сообщении. Больше клиентов — в заметки по настройке клиентов.

Убедитесь, что отдают настоящую модель#

Сначала проверьте эндпоинт, а не клиент — если это не работает, настройки не помогут:

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

Сначала проверьте эндпоинт вне ST, затем сравните сложный промпт с официальным API при temperature 0:

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

Проверяйте нас, а не верьте на слово

Направьте открытый бенчмарк на DaoXE и на официальный API и сравните при temperature 0. Затем изучите, как поймать подмену модели, чтобы дешёвый эндпоинт не подменил вам модель на меньшую.

Частые вопросы#

SillyTavern умеет DaoXE?

Да — Chat Completion → Custom (OpenAI-compatible): Base URL https://daoxe.com/v1, ключ и точный ID модели.

Добавлять ли /chat/completions в URL?

Нет — SillyTavern дописывает его сам. Base URL заканчивается на /v1; ручной суффикс — самая частая причина 404.

Список моделей не заполняется — что делать?

Впишите ID вручную в Enter a Model ID. ST откатывается к текстовому полю, когда список с эндпоинта не пришёл; если эндпоинт работает, Bypass API status check уберёт предупреждение.

Сколько стоит?

По моделям и аккаунту — актуальные цены; пополнение — фиксированные 1 ¥ = $1 квоты.
