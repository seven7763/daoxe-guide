DaoXE в Obsidian Copilot

Copilot — самый популярный AI-плагин Obsidian. Его BYOK принимает любой OpenAI-совместимый эндпоинт как кастомный провайдер: один ключ DaoXE делает чат и агентные функции хранилища мульти-вендорными.

Обновлено 2026-07-20

Путь Settings → Copilot → BYOK → Add a provider → Add a custom provider принимает base URL, ключ и ID моделей — ровно то, что даёт DaoXE. Одна настройка, и Quick Chat и агентные функции достают GPT, Claude, Gemini, DeepSeek и весь каталог аккаунта с одного баланса (гайд по дешёвым API).

Зачем направлять Obsidian Copilot через DaoXE#

  • AI там, где ваши заметки. Чат, правки и суммаризация по хранилищу без копирования в другое приложение.
  • Один ключ, много вендоров. Никаких аккаунтов вендоров внутри плагина.
  • Ключи в Keychain. BYOK-ключи хранятся в Keychain устройства, а не в data.json хранилища — синхронизация не уносит ключи.

Настройка в Obsidian Copilot#

  1. Откройте BYOK. Obsidian → Settings → Copilot → BYOK → Add a provider → Add a custom provider.
  2. Base URL и ключ. https://daoxe.com/v1 и ваш ключ DaoXE. Base URL — до /v1; пути плагин дописывает сам.
  3. Точные ID моделей. Обнаружение читает /v1/models; если список не пришёл, впишите точный ID из GET /v1/models вручную — придуманные не работают.
  4. Test и настройка списков. Нажмите Test и Save. Новые модели включаются для Quick Chat и агентов по умолчанию; списки собираются в Basic → Agents.

Что важно учесть

CORS: если Test прошёл, а чат не отправляется — включите Enable CORS у провайдера; ответы будут приходить целиком, без потоковой передачи. Маршрутизация агентов: ключи передаются агентному бэкенду при старте; модель, которую он не может маршрутизировать, остаётся вне агентного списка, но может работать в Quick Chat. Хранение ключа: Keychain устройства, удаление — Advanced → API Key Storage. ID моделей привязаны к аккаунту. Больше клиентов — в заметки по настройке клиентов.

Убедитесь, что отдают настоящую модель#

Сначала проверьте эндпоинт, а не клиент — если это не работает, настройки не помогут:

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

Проверьте эндпоинт вне клиента, затем сравните сложный промпт с официальным API при temperature 0:

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

Проверяйте нас, а не верьте на слово

Направьте открытый бенчмарк на DaoXE и на официальный API и сравните при temperature 0. Затем изучите, как поймать подмену модели, чтобы дешёвый эндпоинт не подменил вам модель на меньшую.

Частые вопросы#

Copilot умеет DaoXE?

Да — BYOK → Add a custom provider: base URL https://daoxe.com/v1, ключ и точные ID моделей.

Test проходит, а чат — нет?

Это случай CORS: включите Enable CORS у провайдера. После этого ответы приходят без стриминга.

Где хранится ключ?

В Obsidian Keychain устройства — не в data.json, поэтому синхронизация хранилища ключ не копирует.

Сколько стоит?

По моделям и аккаунту — актуальные цены; пополнение — фиксированные 1 ¥ = $1 квоты.
