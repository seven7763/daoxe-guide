DaoXE в OpenClaw

OpenClaw — открытый персональный ИИ-ассистент, живущий в ваших чат-каналах и выполняющий реальные задачи на ваших машинах. Слой моделей настраивается конфигом: один блок models.providers делает DaoXE полноправным провайдером.

Обновлено 2026-09-15

Gateway OpenClaw берёт все модели агентов из ~/.openclaw/openclaw.json — это JSON5 с хот-релоадом. Документация о кастомных провайдерах называет форму DaoXE буквально: api: "openai-completions" за base URL с /v1 — именно так описывается любой OpenAI-совместимый сервер (гайд по дешёвым API).

Зачем направлять OpenClaw через DaoXE#

  • Один ключ на целого ассистента. Чаты, cron-задачи, субагенты и циклы инструментов резолвятся через объявленные провайдеры — ключ DaoXE покрывает сотни моделей от ~25 провайдеров: и «планировщик», и дешёвый рабочий.
  • Метаданные ваши. Окно контекста, модальности входа и лимиты вывода объявляются в вашем конфиге, а не угадываются клиентом.
  • Полная обозревемость. Один блок JSON5 точно описывает, что и куда отправляется — скрытой маршрутизации между ассистентом и эндпоинтом нет.

Настройка в OpenClaw#

  1. Зарегистрируйте провайдера. В ~/.openclaw/openclaw.json в models.providers добавьте запись daoxe: baseUrl: "https://daoxe.com/v1", api: "openai-completions", apiKey: "${DAOXE_API_KEY}" — форма подстановки из env, как в доках.
  2. Зарегистрируйте и модели. Добавьте models: [{ id: "YOUR_EXACT_MODEL_ID" }] — точь-в-точь из GET /v1/models DaoXE, а моделям со зрением укажите input: ["text", "image"]. Запись провайдера без явных строк моделей не регистрирует ничего.
  3. Назначьте дефолты. agents.defaults.model.primary = "daoxe/YOUR_EXACT_MODEL_ID" — ссылки всегда вида provider/model. Алиасы и настройки по моделям — опционально, в agents.defaults.models.
  4. Сохраните и проверьте. Gateway следит за файлом и применяет изменения сам; аддитивные правки можно давать через openclaw config set models.providers.daoxe '<json>' --strict-json --merge (разрушительная перезапись требует --replace). Проверьте openclaw models list и переключитесь openclaw models set daoxe/….
json5
// ~/.openclaw/openclaw.json — add DaoXE as a custom provider
{
  env: { vars: { DAOXE_API_KEY: "sk-you…-key" } },
  agents: {
    defaults: {
      model: { primary: "daoxe/YOUR_EXACT_MODEL_ID" },
    },
  },
  models: {
    mode: "merge",
    providers: {
      daoxe: {
        baseUrl: "https://daoxe.com/v1",
        apiKey: "${DAOXE_API_KEY}",
        api: "openai-completions",
        models: [
          { id: "YOUR_EXACT_MODEL_ID", name: "DaoXE primary",
            input: ["text", "image"], contextWindow: 200000 },
        ],
      },
    },
  },
}

Что важно учесть

Провайдер — ещё не модель: документация прямо пишет, что agents.defaults.models["provider/model"] «никоим образом не регистрирует новую рантайм-модель» — каждая кастомная модель обязана ещё и появиться в models.providers.daoxe.models[] с точным id. Vision включается вручную: без input модель считается текстовой, и картинки доходят как текстовые ссылки, а не пиксели — отмечайте способные модели явно. Compat-флаги форсируются: на не-нативных маршрутах openai-completions OpenClaw шлёт роль system вместо OpenAI-рольной developer и пропускает OpenAI-специфичный шейпинг запроса; явный supportsDeveloperRole: true всё равно переопределяется — не боритесь с этим. Оценку стоимости пишете вы: пропущенный блок cost дефолтится нулями, поэтому счётчики OpenClaw покажут $0 на маршруте DaoXE, хотя аккаунт тарифицируется на сервере — заполните реалистичными цифрами, если смотрите эту панель. Больше клиентов — в заметки по настройке клиентов.

Убедитесь, что отдают настоящую модель#

Сначала проверьте эндпоинт, а не клиент — если это не работает, настройки не помогут:

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

Сначала проверьте эндпоинт вне ассистента, затем сравните сложный промпт с официальным API при temperature 0:

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

Проверяйте нас, а не верьте на слово

Направьте открытый бенчмарк на DaoXE и на официальный API и сравните при temperature 0. Затем изучите, как поймать подмену модели, чтобы дешёвый эндпоинт не подменил вам модель на меньшую.

Частые вопросы#

OpenClaw работает с DaoXE?

Да — запись daoxe в models.providers: api: "openai-completions", baseUrl: "https://daoxe.com/v1", ваш ключ и явные строки моделей; затем agents.defaults.model.primary на daoxe/<id>.

Работает ли нативный Claude Messages от DaoXE?

Как второй провайдер — да: документация поддерживает api: "anthropic-messages" для совместимых маршрутов. Учтите: на не-прямых Anthropic-маршрутах OpenClaw подавляет неявные beta-заголовки, так что headers["anthropic-beta"] при нужде ставьте явно.

Почему модели нет в пикере?

Потому что запись провайдера сама по себе моделей не регистрирует — добавьте совпадающую строку { id: "…" } в массив models провайдера с точным ID из GET /v1/models.

Сколько стоит?

По моделям и аккаунту — актуальные цены; пополнение — фиксированные 1 ¥ = $1 квоты.
