DaoXE в Raycast AI

В лаунчере Raycast встроены AI-чат, Quick AI и AI Extensions. Custom Providers принимает любой OpenAI-совместимый эндпоинт через YAML-файл — один ключ DaoXE питает все AI-поверхности лаунчера.

Обновлено 2026-07-20

Custom Providers Raycast читает ~/.config/raycast/ai/providers.yaml и регистрирует объявленные модели во всех AI-функциях — чат, Quick AI, AI Extensions. Одна запись на DaoXE, и выборщик моделей лаунчера охватывает GPT, Claude, Gemini, DeepSeek и весь каталог аккаунта на одном балансе (гайд по дешёвым API).

Зачем направлять Raycast AI через DaoXE#

  • AI в слое хоткеев. Одни и те же модели везде, где Raycast спрашивает модель — без переключения приложений.
  • Один ключ, много вендоров. Кросс-вендорные шлюзы — явно поддерживаемый сценарий, а не хак.
  • Прямая маршрутизация. Запросы идут с устройства прямо на эндпоинт — серверы Raycast вне пути.

Настройка в Raycast AI#

  1. Откройте Custom Providers. Raycast → Settings → AI → прокрутите до Custom Providers → Reveal Providers Config. Скопируйте providers.template.yaml в providers.yaml.
  2. Опишите провайдера. Запись с base_url: https://daoxe.com/v1 (без суффикса /chat/completions) и ваш ключ в api_keys.
  3. Зарегистрируйте точные ID. Каждой модели нужен id из GET /v1/models, показываемое name и реалистичный context. Придуманные ID падают на запросе.
  4. Честно укажите abilities. Объявляйте то, что модель реально умеет — tools для AI Extensions, vision для картинок. Сохраните; файл подхватывается без перезапуска.
yaml
# ~/.config/raycast/ai/providers.yaml
providers:
  - id: daoxe
    name: DaoXE
    base_url: https://daoxe.com/v1
    api_keys:
      daoxe: sk-you…-key
    models:
      - id: <exact-model-id>
        name: GLM 5.3 Flash
        provider: daoxe
        context: 128000
        abilities:
          tools: {supported: true}
          vision: {supported: true}

Что важно учесть

Нужен Pro. Custom Providers — функция тарифа Pro; в бесплатном секция не появится. Значения по умолчанию: необъявленная способность означает system-message и temperature включёнными, tools и vision выключенными — модель, которая умела tools, молча их не получит. Бейдж валидации: битый YAML показывает бейдж Invalid providers.yaml рядом с Providers Config; наведите для текста ошибки, а уже загруженные модели продолжают работать. OpenAI API — не стандарт: в доках Raycast прямо сказано, что совместимость с каждым провайдером не гарантируется — проверьте один чат перед раскаткой. Больше клиентов — в заметки по настройке клиентов.

Убедитесь, что отдают настоящую модель#

Сначала проверьте эндпоинт, а не клиент — если это не работает, настройки не помогут:

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

Проверьте эндпоинт вне клиента, затем сравните сложный промпт с официальным API при temperature 0:

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

Проверяйте нас, а не верьте на слово

Направьте открытый бенчмарк на DaoXE и на официальный API и сравните при temperature 0. Затем изучите, как поймать подмену модели, чтобы дешёвый эндпоинт не подменил вам модель на меньшую.

Частые вопросы#

Raycast AI умеет DaoXE?

Да — Custom Providers: запись в providers.yaml с base_url: https://daoxe.com/v1, ключом и точными ID моделей.

Нужен ли Raycast Pro?

Да, для Custom Providers. В бесплатном тарифе секция не отображается.

Почему у модели не работают tools?

Способности tools и vision по умолчанию выключены — объявите supported: true, только если модель реально их поддерживает.

Сколько стоит?

По моделям и аккаунту — актуальные цены; пополнение — фиксированные 1 ¥ = $1 квоты.
