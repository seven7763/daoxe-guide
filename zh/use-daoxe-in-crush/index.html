在 Crush 里用 DaoXE

Crush 是 Charm Bracelet 的终端编码智能体。它的 openai-compat 供应商类型接受任何 OpenAI 形状的端点 —— DaoXE 只差 crushrc 里的两条命令。

更新于 2026-07-20

Crush 在终端里跑智能体编码会话：改文件、执行命令、读项目的上下文文件。它的配置是一个 Bash 文件，非 OpenAI 端点的供应商路径就是 openai-compat 类型 —— 正是 DaoXE 的形状（最便宜 API 教程）。

为什么让 Crush 走 DaoXE#

  • 智能体级编码，用你自己的模型。Crush 的规划、编辑和工具调用都走你注册的供应商 —— 一把 DaoXE key 覆盖 ~25 家供应商的数百个模型。
  • 配置就是 Bash 文件。crushrc 启动时像 .bashrc 一样执行，key 可以来自密码管理器，不必躺在 JSON 里。
  • large / small 模型槽。主循环用强模型、后台任务用便宜模型，正好映射到 DaoXE 的目录。

在 Crush 里配置#

  1. 注册供应商。 在 ~/.config/crush/crushrc：provider add daoxe --type openai-compat --base-url "https://daoxe.com/v1" --api-key "${DAOXE_API_KEY:?set DAOXE_API_KEY}" —— 文档自带的 openai-compat 示例就是以 /v1 结尾的 base URL 加 shell 展开的 key。
  2. 注册模型。 model add daoxe/YOUR_EXACT_MODEL_ID 用 GET /v1/models 的精确 ID，加上 --context-window，可选 --can-reason / --supports-images —— 这些能力标志决定 Crush 会向模型要求什么。
  3. 填模型槽。 主循环用 model large daoxe/YOUR_EXACT_MODEL_ID；后台任务用 model small daoxe/YOUR_SMALL_MODEL_ID。引用一律是 provider/model 形式 —— 也就是 crush models 打印的形式。
  4. 开始会话。 在项目里运行 crush；TUI 会列出该供应商的模型。crush models 打印当前 large/small 选择。
bash
# ~/.config/crush/crushrc — register DaoXE as an openai-compat provider
provider add daoxe \
  --type openai-compat \
  --base-url "https://daoxe.com/v1" \
  --api-key "${DAOXE_API_KEY:?set DAOXE_API_KEY}"

# register a model, then put it in the large (coding) slot
model add daoxe/YOUR_EXACT_MODEL_ID --name "DaoXE primary" --context-window 128000
model large daoxe/YOUR_EXACT_MODEL_ID

值得注意的坑

模型按供应商注册：Crush 读取 models 列表并能合并自动发现的条目 —— discover_models 默认开启时你的显式条目优先于拉取的，但只有供应商条目、没注册过模型的仍然要 model add。上下文窗口自己填：文档示例总是传 --context-window；填错影响的是 Crush 的摘要与截断逻辑，不是 API。key 是 shell 展开的：crushrc 就是 Bash —— ${DAOXE_API_KEY:?…} 在变量为空时会大声失败，而空的 --api-key 会原样发出去，所以保护性展开不能省。受信任的配置：Crush 以你的 shell 权限执行 crushrc，文档明确警告不要在没读过配置的目录里启动 —— DaoXE key 放你自己的 crushrc，别放项目里的。更多客户端见客户端设置说明。

验证你拿到的是真模型#

先证明端点可用，再怀疑客户端 —— 这一步失败，改任何设置都没用：

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

先在智能体之外验证端点，再在 temperature 0 下把难题与官方 API 对比：

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

常见问题#

Crush 能接 DaoXE 吗？

能 —— provider add daoxe --type openai-compat --base-url "https://daoxe.com/v1" 加 key，然后 model add daoxe/YOUR_EXACT_MODEL_ID。

openai 还是 openai-compat？

openai-compat —— Crush 的 README 写明它用于「有 OpenAI 兼容 API 的非 OpenAI 供应商」；openai 是经 OpenAI 本身代理用的。

为什么 Crush 看不到我的模型？

模型来自该供应商注册的列表（开启发现时会合并）。用 model add daoxe/YOUR_EXACT_MODEL_ID 注册 —— 只有供应商条目不会带来任何模型。

费用？
