在 Dify 里用 DaoXE

Dify 是开源 LLM 应用平台 —— chatflow、workflow、agent。它的 OpenAI-API-compatible 模型供应商接受任何 OpenAI 形态端点，一个 DaoXE key 就能给工作区里每个应用的每个模型供电。

更新于 2026-07-20

Dify 通过供应商插件接入模型。从 Marketplace 安装 OpenAI-API-compatible 插件，把 DaoXE 加为自定义模型，Dify 的每个应用 —— 聊天、工作流、智能体 —— 就都能调用你的 DaoXE 目录（最便宜 API 教程）。模型是逐个声明的，所以真正的配置都在每个模型的字段里。

为什么让 Dify 走 DaoXE#

  • 应用继承模型。 一个工作区级供应商服务 chatflow、workflow 和 Agent 节点。
  • 逐模型能力开关。 上下文长度、function-call 类型、视觉支持都按模型声明 —— 应用知道自己能做什么。
  • 自部署或云端皆可。 两者用同一个供应商、同一个端点。

在 Dify 里配置#

  1. 安装供应商。 Integrations → Model Provider（或 Marketplace），安装 OpenAI-API-compatible。
  2. 添加模型。 在供应商卡片上点 Add Model。Model Name 必须是 GET /v1/models 里的精确 ID；Model Type 选 LLM。
  3. 填 API Base URL。 LLM 类型填 https://daoxe.com/v1。embedding/rerank 类型不要带 /v1 —— 插件内部会自己补，全 URL 会导致路径重复。
  4. 填能力字段。 API Key = DaoXE key；Completion mode = Chat；Model context size = 模型真实窗口；Upper bound for max tokens = 合理上限；Function Call Type = 模型支持就选 Tool Call；Vision Support 按模型实际情况。

值得注意的坑

/v1 规则按模型类型分：插件自己的文档里 LLM 用带 /v1 的 base URL，embedding/rerank/STT/TTS 用裸主机 —— 这些路径由插件内部补全，填错会产生重复路径并 404。Function Call Type 默认 Not Support：不改的话 Agent 节点永远不会调工具 —— 模型真支持就设 Tool Call（以及流式工具调用字段）。Context size 默认 4096：远小于模型真实窗口时会静默截断长 prompt。智能体需要原生工具调用：Dify 官方排障文档明说 OpenAI 兼容端点常常缺完整工具支持 —— 按此选模型。Token parameter name：部分新模型要求 max_completion_tokens；自动判断错了就显式指定。更多客户端见客户端设置说明。

验证你拿到的是真模型#

先证明端点可用，再怀疑客户端 —— 这一步失败，改任何设置都没用：

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

先用一个应用测通供应商，再在 temperature 0 下把难题与官方 API 对比：

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

常见问题#

Dify 该选哪个供应商？

安装 OpenAI-API-compatible 插件，把 DaoXE 加为自定义模型：精确 ID、key 和 API Base URL。

为什么 embedding 端点 404？

embedding/rerank/STT/TTS 类型下插件会自己补版本路径 —— 那里填裸主机（不带 /v1），/v1 只留给 LLM 模型。

为什么 Agent 不调工具？

模型条目上的 Function Call Type 默认 Not Support —— 改成 Tool Call，并用真正支持 function calling 的模型。

怎么收费？

按模型、随账号 —— 实时定价；充值统一 1 元 = $1 额度。
