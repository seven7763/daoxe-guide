在 LobeChat 里用 DaoXE

LobeChat 是接受任何 OpenAI 兼容供应商的开源聊天 UI。一个 DaoXE 端点就能点亮它整个模型选择器 —— GPT、Claude、Gemini、DeepSeek —— 给你或整个团队。

更新于 2026-07-20

LobeChat 的供应商设置说 OpenAI 兼容 HTTP，所以 DaoXE 作为自定义端点直接入座：粘贴 key、指好 URL，它的模型拉取会直接读你账号的 GET /v1/models。这是给非技术用户开「一扇门用很多模型」的最快方式 —— 门后的价格逻辑见最便宜 API 教程。

为什么让 LobeChat 走 DaoXE#

  • 选择器即你的目录。 你的 key 能调的都会出现，不能调的一个都不会。
  • 官方托管或自建皆可。 LobeChat 云端版和你自己的 Docker 实例吃同一个端点。
  • 支持之处即有多模态与工具。 目录里支持视觉 / function calling 的模型会表现出各自的本色。

在 LobeChat 里配置#

  1. 打开供应商设置。 LobeChat 设置 → 语言模型 → OpenAI（或添加自定义兼容供应商）。
  2. 填 key 和端点。 粘贴 DaoXE key，端点填 https://daoxe.com/v1。
  3. 拉取模型。 用 LobeChat 的模型列表拉取 —— 它会以你的 key 读 GET /v1/models，勾选要出现在选择器里的 ID。
  4. 跑一次视觉和工具测试。 给支持视觉的 ID 发张图，再跑一个工具任务 —— 然后才推荐队友用。

值得注意的坑

端点到 /v1 为止。只勾选你账号里真实存在的 ID —— LobeChat 会把勾选项展示给实例上的所有人，缺失的 ID 会在对话中途才报错。依赖 embedding 的功能（知识库）需要支持 embedding 的 ID。模型列表随账号：GET /v1/models。更多客户端见客户端设置说明。

验证你拿到的是真模型#

先证明端点可用，再怀疑客户端 —— 这一步失败，改任何设置都没用：

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

先在界面之外证明端点可用，再在 temperature 0 下把难题与官方 API 对比：

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

常见问题#

LobeChat 能接 DaoXE 吗？

能 —— 作为自定义 OpenAI 兼容端点：key 加 https://daoxe.com/v1，然后拉取模型列表。

模型列表会自动填吗？

会用你的 key 读 GET /v1/models。只启用你要的 ID —— 拉取只显示账号真实可调用的模型。

图片输入能用吗？

用目录里支持视觉的模型 ID，且仅在使用该模型的会话里。

费用？

按模型、随账号 —— 见实时定价；充值统一 1 元 = $1 额度。

试用 DaoXE —— 并亲自 benchmark 它

一个 key 调 GPT、Claude、Gemini、DeepSeek 等。用开源 benchmark 对准我们做对比 —— 别只听我们说。
