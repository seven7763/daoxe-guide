在 n8n 里用 DaoXE

n8n 的 OpenAI 凭证接受自定义 Base URL —— 意味着一个 DaoXE key 就能给所有调用模型的节点供电：智能体、聊天、分类、抽取。

更新于 2026-07-20

n8n 里所有说 OpenAI 兼容 HTTP 的 AI 节点都能原样接 DaoXE：建一份凭证、Base URL 指向 DaoXE，整个实例共享模型目录。自动化天生是多模型负载 —— 分流用便宜模型、生成用好模型，节点级的成本拆分见最便宜 API 教程。

为什么让 n8n 走 DaoXE#

  • 一份凭证喂全实例。 智能体、链、路由器共用一个 key 和一个余额。
  • 每个节点配相应档位。 分类步骤不需要顶级模型；智能体的最后一道推理需要。
  • 自托管还是你的。 工作流跑在你的 n8n 上，迁移的只是推理端点。

在 n8n 里配置#

  1. 新建 OpenAI 凭证。 n8n 里 Credentials → New → OpenAI：粘贴 DaoXE key，Base URL 填 https://daoxe.com/v1。
  2. 挂到节点上。 在 AI Agent / OpenAI Chat Model 节点里选择这份凭证，替代默认 OpenAI。
  3. 填模型 ID。 从 GET /v1/models 原样输入 —— 自定义 base URL 上下拉框不会替你猜。
  4. 按步骤分档位。 路由和分类器用便宜模型，生成和智能体主循环用强模型。

值得注意的坑

Base URL 要含 /v1 —— 其余路径 n8n 自己补。Embedding 节点需要支持 embedding 的模型 ID（从你的账号列表里取），聊天模型 ID 在那里会失败。智能体节点依赖工具调用，选认真支持的模型。自托管实例需放通到端点的出站 HTTPS。更多客户端见客户端设置说明。

验证你拿到的是真模型#

先证明端点可用，再怀疑客户端 —— 这一步失败，改任何设置都没用：

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

先在任意工作流之外测通凭证，再在 temperature 0 下把难题与官方 API 对比：

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

常见问题#

n8n 支持自定义 OpenAI 兼容端点吗？

支持 —— OpenAI 凭证里有 Base URL 字段，填 https://daoxe.com/v1，所有 OpenAI 形态节点都会继承。

Embedding 能用吗？

能，但要用 GET /v1/models 里支持 embedding 的模型 ID；聊天 ID 在 embedding 节点会失败。

每个节点能各用一个模型吗？

能 —— 节点各自设置模型 ID：路由跑便宜的，生成跑强的。

怎么收费？

按模型、随账号 —— 见实时定价；充值所有支付方式统一 1 元 = $1 额度。
