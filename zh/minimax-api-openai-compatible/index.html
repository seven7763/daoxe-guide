MiniMax API 接入 —— OpenAI 兼容，一个 key

MiniMax 的 M 系列和其他模型一样，走 DaoXE 的标准 OpenAI 兼容 base URL —— 不用单独的 SDK，不用过中文控制台的注册流程。一个 key、目录 ID、可验证。

更新于 2026-07-20

DaoXE 用标准 OpenAI 形态承载 MiniMax M 系列：POST /v1/chat/completions 加 MiniMax 模型 ID；支持的 ID 可走 /v1/responses。现有 OpenAI SDK 代码原样运行 —— 只改 base URL 和 key。真实省钱逻辑见最便宜 API 教程。

通过 DaoXE 调用 MiniMax#

Chat 路径：/v1/chat/completions，用 Authorization: Bearer。MiniMax 推理型 ID 默认就思考 —— M2.x 的思考根本关不掉。extra_body={"reasoning_split": True} 并不切换思考：它只是把思维链挪进 reasoning_details，而不是留在 content 里。

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'
python
# MiniMax reasoning IDs think by DEFAULT; on M2.x thinking cannot be turned
# off. reasoning_split only changes WHERE the thinking lands - without it the
# chain of thought stays fused into the text.
from openai import OpenAI

client = OpenAI(base_url="https://daoxe.com/v1", api_key="YOUR_DAOXE_KEY")
r = client.chat.completions.create(
    model="YOUR_EXACT_MODEL_ID",   # a MiniMax-* id from GET /v1/models
    messages=[{"role": "user", "content": "2+2? Think briefly, then answer."}],
    extra_body={"reasoning_split": True},
)
msg = r.choices[0].message
details = getattr(msg, "reasoning_details", None)  # thinking, when split is on
print(details[0]["text"] if details else None)
print(msg.content)                                 # final answer

MiniMax 如何暴露思考内容#

MiniMax 推理型 ID 默认就思考：在 MiniMax 的 OpenAI 兼容 API 里，M3 的 thinking 控制默认 {"type": "adaptive"} —— 由模型自行决定何时思考 —— 而 M2.x 系列的思考完全无法禁用。把思维链从回答里分离出来是另一个独立开关：传 extra_body={"reasoning_split": True}，思考内容会放进 reasoning_details；不开标志就留在 content 里。分离标志从不决定思考的开与关 —— 如果流程需要机器可读的推理，就每次调用都带上它。

MiniMax 特有的注意点#

  • 思考默认开着；M2.x 关不掉。 在 MiniMax 的 OpenAI 兼容 API 里，M3 的 thinking 控制默认 adaptive，而 M2.x 系列的思考完全无法禁用。reasoning_split 不切换思考 —— 它只决定思维链是落到独立字段还是留在 content 里。
  • 上游的协议面。 MiniMax 自家 API 有 Messages 兼容面；某个中转路径是否承载它，正是需要验证的事 —— 在把客户端绑上去之前先发一条 Messages 调用试试。
  • 只用实时列表的准确 ID。 M 系列版本在动（当前 M3 / M2.7 / M2.5）；从 GET /v1/models 复制，别照搬发布稿。

这要花多少钱#

一个余额，一个充值汇率

充值统一按 1 元人民币 = $1 额度，所有支付方式一致；模型再各按自己的美元标价计费 —— 实时单价见定价页。支付宝、微信、USDT、银行卡（Visa · Mastercard）、Apple Pay 与 Google Pay 都是同一个汇率 —— 目录里所有模型共用一个余额，不用选套餐，也没有月度低消。单价与账户绑定且会变动，所以请用一小笔充值去确认，而不是相信教程里的某个数字。

常见问题#

需要 MiniMax 控制台账号吗？

不需要 —— MiniMax 挂在你的单一 DaoXE key 下，用 GET /v1/models 里的普通目录 ID。

为什么没有单独的思考字段？

设 extra_body={"reasoning_split": True}；这个标志只决定思考落在哪，不决定模型是否思考 —— MiniMax 推理型 ID 默认就思考，M2.x 的思考关不掉。

MiniMax 能用哪些端点？

OpenAI 兼容 chat（/v1/chat/completions）、支持的 ID 可用 Responses、声明支持的 ID 可用 Anthropic 形态 Messages。

这里 MiniMax 多少钱？

按模型、按账号 —— 见实时定价。充值统一 1 元 = $1 额度。
