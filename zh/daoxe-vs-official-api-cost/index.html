DaoXE vs 官方 API 成本对比，诚实拆解

网关与官方的成本不是单一数字，而是账单开销、按模型路由，以及你是否信任拿到的东西。这里给出框架，再给出四步算清你自己成本的方法 —— 而不是一张等你读到时早就过期的价格表。

更新于 2026-07-20

你到底在为什么付费#

用官方 API，你按各家每百万输入/输出 token 的标价付费，还有多账号的隐性开销：分别绑卡、分别开票，很多地区还会支付失败。网关改变了账单形态：一个 key、一个余额、按模型计价，并可把便宜任务路由到便宜模型。

一笔 DaoXE 账单是怎么算出来的#

没有套餐、没有席位、没有月度低消：你先充值成余额，每次请求从余额里扣。单次调用花多少，由四件事决定，而这四件事在你花钱之前都能查清楚。充值统一按 1 元人民币 = $1 额度，所有支付方式一致；模型再各按自己的美元标价计费 —— 实时单价见定价页。

决定账单的因素含义在哪里查
模型本身目录里每个模型都有自己的输入价与输出价，按美元/百万 token 标价；部分图像与视频模型按次计费，不按 token。定价页；你的 key 能调用的准确 ID 见 GET /v1/models
渠道分组同一个模型可能由多条上游渠道提供，每个分组各有自己的倍率 —— 所以同一个模型 ID 会因为你的 key 走哪个分组而有不同单价。定价页上的分组列；你的 key 可用哪些分组，在账户里可以看到
实际消耗的 token该请求的输入 + 输出 token。思考 token 和工具调用的每一轮往返都算钱 —— 这就是智能体类工作负载比「按 prompt 长度估算」贵得多的原因。每次响应返回的 usage 对象，以及账户里的用量记录
你的充值汇率额度按 1 元 = $1 购买，支付宝、微信、USDT、银行卡（Visa · Mastercard）、Apple Pay、Google Pay 一视同仁。钱包页 —— 充一小笔，一分钟内就能自己确认
单价与账户、分组绑定且会变动，所以本教程只讲机制并指向实时来源，而不是印一张等你读到时早已过期的数字表。

四步算清你自己的成本#

  1. 查你这个模型的实时单价。 打开定价页，找到你的准确模型 ID，记下你的 key 实际使用的那个分组的输入/输出价 —— 不是页面上最便宜的那个分组。
  2. 查厂商自己的官方标价。 打开该模型厂商的官方定价页（见下方链接）查同一个模型，这样才是同口径对比，而不是跟记忆里的一个数字比。
  3. 实测一次真实请求。 在 temperature=0 下发一个小请求，从响应里读 usage.prompt_tokens 与 usage.completion_tokens，再核对账户实际扣了多少额度。
  4. 换算成真实的一个月。 乘以你真实的月度 token 量 —— 把重试、每轮都重发的系统提示、思考 token 都算进去。成本估算翻车通常翻在这里，而不是单价上。

这一页为什么没有价格表

这里的单价与账户、分组绑定，而分组倍率正在调整 —— 今天印出来的表，对一个月后打开这页的人就是错的数字。所以诚实的说法是：唯一权威的价格是定价页，公平的对照是各厂商自己的官方页，而充一小笔 + 实测一次请求大约一分钟就能把问题问清楚。各厂商官方定价页：Anthropic · Google · OpenAI · xAI · DeepSeek。

支付与充值#

先充值成额度，再按请求消耗；没有订阅制，没用完的余额就一直是余额。充值统一按 1 元人民币 = $1 额度，所有支付方式一致；模型再各按自己的美元标价计费 —— 实时单价见定价页。

方式是否支持充值汇率
支付宝支持1 元 = $1 额度
微信支持1 元 = $1 额度
USDT（加密）支持按当日等值人民币折算后，同样 1 : 1
银行卡（Visa · Mastercard）支持1 元 = $1 额度
Apple Pay支持1 元 = $1 额度
Google Pay支持1 元 = $1 额度
支付方式经确认 2026-08-10。结账时具体出现哪几种与地区有关，最低充值额由支付服务商设定 —— 以支付页显示为准。

用你能充的最小金额去验证

充值汇率和各模型单价都由服务方设定，而且都可能变动 —— 所以任何地方看到的数字（包括本教程里的）都应当去核实，而不是默认成立。充一小笔 + 实测一次请求，大约一分钟就能知道你的真实成本。实时单价见定价页。

网关何时省钱、何时不#

省钱，当…

你用多家供应商、把便宜任务路由到便宜模型，或直连时遇到支付/地区门槛。

持平，当…

你只用一款模型且高用量、官方账单已跑通 —— 这时直接比每 token 单价。

只有在…才值

你能验证真伪。便宜但不可验证是假省钱。

账单如何保持透明#

  • 定价页上按模型、按 token 计价。
  • 账户维度的模型列表 —— 你看到的就是你能调的。
  • 用开源 benchmark独立验证 —— 数字不用靠信。

这些数字请你自己确认

按模型的单价只在 daoxe.com/pricing 上，本教程任何地方都不写。注册赠额 待确认、可用率 建议自行监测 由服务方给出、由你测量 —— 官方没有公开的可用率数据，所以任何可用率数字（包括厂商自己写的）在你实测之前都只是宣称。

一次运行就验证成本优势#

最公平的做法：在 temperature=0 下用同一 prompt 分别跑 DaoXE 和官方 API，对比 token 用量、延迟与输出。基准教程把这一步自动化。

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "你的准确模型ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "用一句话打个招呼"}]
  }'

常见问题#

DaoXE 比官方 API 便宜吗？

对某些模型、某些用法是 —— 但它不是一刀切的折扣，本教程也刻意不写任何百分比。请用上面那四步算你自己的情况：把你那个模型在定价页上的实时单价，与厂商官方标价对照，再实测一次请求确认。

这一页为什么不列价格表？

因为单价与账户、分组绑定，而且会变 —— 在这里印一张表，几周后就是在给读者错的数字。唯一权威的是实时定价页；上面那四步能在一分钟左右把它和厂商官方价对照清楚。

用量怎么计费？

按模型、按 token（输入/输出）在一个余额上计。以你账户的用量页和定价页为准。

怎么确认省下的钱不是换了降级模型？

去验证：用开源 benchmark对准 DaoXE 和官方 API 做对比。
