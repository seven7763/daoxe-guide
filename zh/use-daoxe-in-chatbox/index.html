在 Chatbox 里用 DaoXE

Chatbox 是流行的开源桌面客户端（Win / macOS / Linux），它的 Custom Provider 接受任何 OpenAI 兼容端点。一个 DaoXE key 就把它变成多厂商控制台。

更新于 2026-07-20

Chatbox 的 Custom Provider 只要 API host 和 key —— 这正是 DaoXE 的形态。配一次，客户端的模型选择器就能在一个余额里触达 GPT、Claude、Gemini、DeepSeek 和你账号目录里的其余模型（最便宜 API 教程）。

为什么让 Chatbox 走 DaoXE#

  • 桌面应用、历史在本地。 对话留在自己机器上，出去的只有推理请求。
  • 一个 key，多家厂商。 客户端里不用塞各家账号和卡。
  • 群聊与提示词库。 多模型群聊、提示词库都跑在同一个端点上。

在 Chatbox 里配置#

  1. 打开设置。 Chatbox → 设置 → 模型服务商 → 选 自定义服务商（或添加服务商）。
  2. 填 API 地址。 https://daoxe.com/v1 —— 到 /v1 为止，路径 Chatbox 自己补。
  3. 粘贴 key。 DaoXE key；模型列表可自动拉取，或从 GET /v1/models 原样粘贴 ID。
  4. 发一条测试。 短消息一条；再核对响应里的 model 字段与请求一致。

值得注意的坑

API 地址到 /v1 为止。桌面版 Chatbox 默认经内置代理中继（处理 CORS）；自建 / API 模式下把同样的 host 和 key 填进去即可。模型 ID 与账号绑定 —— GET /v1/models。视觉 / 工具能力取决于所选模型而非客户端。更多客户端见客户端设置说明。

验证你拿到的是真模型#

先证明端点可用，再怀疑客户端 —— 这一步失败，改任何设置都没用：

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

先在客户端之外验证端点，再在 temperature 0 下把难题与官方 API 对比：

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

常见问题#

Chatbox 能接 DaoXE 吗？

能 —— Custom Provider：API host 填 https://daoxe.com/v1 加 key，行为等同任何 OpenAI 兼容端点。

模型名从哪来？

端点自动拉取，或从 GET /v1/models 原样粘贴 —— 猜的名字会失败。

代理模式是什么？

桌面版默认把请求经自家中继转发以绕 CORS；API 模式下则是直连，host/key 相同。

怎么收费？

按模型、随账号 —— 实时定价；充值统一 1 元 = $1 额度。
