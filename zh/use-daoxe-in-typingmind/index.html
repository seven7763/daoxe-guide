在 TypingMind 里用 DaoXE

TypingMind 是完全跑在你浏览器里的 BYOK 聊天前端。它的 Add Custom Model 对话框接受任何 OpenAI 形状的端点 —— DaoXE 就差一个对话框。

更新于 2026-07-20

TypingMind 是自带 key 的前端：聊天、设置与 API key 都留在浏览器里，请求直接发往你指定的供应商。Add Custom Model 对话框就是通用的 OpenAI 兼容设置面 —— 正是 DaoXE 的形状（最便宜 API 教程）。

为什么让 TypingMind 走 DaoXE#

  • key 不出浏览器。TypingMind 文档明确：数据与 API key「存储在浏览器本地，永远不会发到 TypingMind 的服务器」。
  • 网页版与静态自托管版通用。自定义模型流程一致 —— 私有部署上也能接 DaoXE。
  • 逐模型控制。上下文长度、插件与视觉开关都按自定义模型设置 —— 每个 DaoXE 模型能做什么由你决定。

在 TypingMind 里配置#

  1. 打开对话框。 点左侧边栏的 Models 图标，再点 + Add Custom Model（右上角）—— 与 TypingMind 文档给 Ollama、LM Studio、LocalAI 用的是同一流程。
  2. 选 API 类型。 选 OpenAI 类型（文档的 Gemini 示例里有 API Type 选择器 —— DaoXE 选 OpenAI 这一档）。
  3. 粘贴完整端点。 Endpoint：https://daoxe.com/v1/chat/completions。TypingMind 文档示例都带完整路径（如 LM Studio 的 http://localhost:1234/v1/chat/completions）—— 不是裸 base URL。
  4. 模型 ID、请求头、Test。 填 GET /v1/models 里的精确模型 ID，设上下文长度，加一行自定义请求头（Authorization : Bearer sk-…）放 key，然后点 Test —— 应用会在保存前检查端点与能力。

值得注意的坑

endpoint 是完整路径：文档里每个自定义模型示例都以 /chat/completions 结尾；只给 base URL 会在 Test 一步失败。模型 ID 手动填：自定义模型没有模型列表拉取 —— 从 GET /v1/models 照抄精确 ID，一条配置一个模型。key 放请求头：文档把自定义 key 走 Custom Headers 行（它的 Gemini 示例用 apiKey）；OpenAI 形状的端点用 Authorization: Bearer。浏览器来源很重要：请求从你的浏览器直发端点，所以 http://localhost 上的自托管 TypingMind 可能撞上 https 托管版不会遇到的 CORS 墙 —— 一边 Test 通过另一边失败，差别就在这里。先 Test 再保存：按钮会检查端点并探测能力；ID 或路径错了会在那里暴露，而不是进聊天才发现。更多客户端见客户端设置说明。

验证你拿到的是真模型#

先证明端点可用，再怀疑客户端 —— 这一步失败，改任何设置都没用：

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

先在应用之外验证端点，再在 temperature 0 下把难题与官方 API 对比：

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

常见问题#

TypingMind 能接 DaoXE 吗？

能 —— Models → Add Custom Model → OpenAI 类型，endpoint 填 https://daoxe.com/v1/chat/completions，key 放自定义请求头。

API key 放哪里？

放 Custom Headers 行 —— Authorization : Bearer sk-你的-daoxe-key。TypingMind 为 Gemini 自定义模型文档了自定义请求头；OpenAI 类型读同样的头约定。

为什么模型列表不会自动填？

TypingMind 的自定义模型是手动输入 —— 文档的 Ollama/LM Studio/LocalAI 页面都要求你手填模型 ID。从 GET /v1/models 照抄精确 ID。
