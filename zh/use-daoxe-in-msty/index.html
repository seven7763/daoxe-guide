在 Msty 里用 DaoXE

Msty 是一个把本地模型和远程 API 放在同一个界面的桌面应用。它的「Open AI Compatible」供应商类型接受任何 OpenAI 形状的端点 —— DaoXE 只差一条供应商配置。

更新于 2026-07-20

Msty 用内置服务跑本地模型，远程供应商则统一走一个设置面。要选的类型就是 Open AI Compatible —— 名称、API endpoint、key —— DaoXE 的形状正好对上（最便宜 API 教程）。

为什么让 Msty 走 DaoXE#

  • 本地与云端同一个选择器。DaoXE 的目录和你的离线模型并排出现在同一个模型选择器里。
  • Workspaces 隔离 key。Msty 的每个工作区各存各的 API key —— 共用机器也能做到一个团队一把 DaoXE key。
  • 模型级附加项。模型的分类（Text / Embedding / Vision / Coding）和额外的 JSON 参数都能跟着自定义供应商走。

在 Msty 里配置#

  1. 打开 Settings → Remote Model Providers。 从侧边栏打开设置，点 Remote Model Providers。
  2. 新增供应商。 点右上角 Add New Provider，在 Models Provider 下拉里选 Open AI Compatible —— Msty 自家文档给 SambaNova 用的就是这条路径。
  3. 填名称、endpoint、key。 名称 DaoXE；API endpoint https://daoxe.com/v1（Msty 文档里的示例全部以 /v1 结尾，例如 https://api.sambanova.ai/v1）；粘贴 DaoXE key。
  4. 添加模型。 先按 Fetch Models —— 成功的话模型名会自动填进来。否则按 GET /v1/models 的精确 ID 手动逐个添加，再点 Add。

值得注意的坑

Fetch Models 是门槛：Msty 官方文档写明，供应商没有可用的 /v1/models 时它「无法自动拉取」——选择器空着就得按精确 ID 手动补模型。endpoint 必须带 /v1：文档里所有 Open AI Compatible 示例都以版本路径结尾，裸域名会 404。key 存在 keychain：Msty 把 key 按 workspace 存进设备 keychain —— 另一台机器导入 workspace 会报「Error while decrypting the ciphertext」，要重新输入 key（或有意选择不加密保存）。模型注册表 ≠ 你的账号：Msty 的模型 registry 与供应商条目相互独立 —— registry 更新不会替你加上 DaoXE 的模型。更多客户端见客户端设置说明。

验证你拿到的是真模型#

先证明端点可用，再怀疑客户端 —— 这一步失败，改任何设置都没用：

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

先在应用之外验证端点，再在 temperature 0 下把难题与官方 API 对比：

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

常见问题#

Msty 能接 DaoXE 吗？

能 —— Settings → Remote Model Providers → Add New Provider → Open AI Compatible，endpoint https://daoxe.com/v1 加 DaoXE key。

为什么模型列表是空的？

Msty 从供应商的 /v1/models 拉模型；请求失败或返回为空，选择器就一直空着。按精确 ID 手动添加模型 —— 这是文档写明的后备方案。

API endpoint 要带 /v1 吗？

要 —— Msty 文档的 Open AI Compatible 示例全部以 /v1 结尾（如 https://api.sambanova.ai/v1）。版本路径保留。

费用？
