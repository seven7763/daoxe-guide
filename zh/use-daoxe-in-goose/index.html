在 goose 里用 DaoXE

goose 是本地优先、可扩展的开源智能体。它的 OpenAI 供应商接受任何兼容端点 —— 指到 DaoXE，一个 key 就能驱动它的规划、编辑和 MCP 工具调用。

更新于 2026-07-20

goose 通过它的 OpenAI 供应商（或 goose configure 里的自定义供应商流程）支持任何 OpenAI 兼容端点，所以接 DaoXE 只是改 base URL 和 key。回报是按 goose 的方式拆分角色：顶级模型负责规划，便宜模型跑重复的工具步骤，见最便宜 API 教程。

为什么让 goose 走 DaoXE#

  • 一个 key 用遍目录。 换智能体模型无需各家开户 —— GET /v1/models 就是实时清单。
  • 按成本拆角色。 贵的推理留给规划，重复的工具步骤用便宜模型。
  • 扩展是要 token 的。 每个接入的 MCP 服务器都是每轮上下文 —— 统一余额让调优不心疼。

在 goose 里配置#

  1. 打开供应商设置。 桌面端进 Models 标签页；CLI 里运行 goose configure，选 Configure Providers。
  2. 选 OpenAI 供应商。 粘贴 DaoXE key；问到 host / base path 时填 https://daoxe.com/v1 —— 到 /v1 为止。
  3. 设置模型。 填从 GET /v1/models 原样复制的模型 ID —— 自定义 host 上 goose 不会替你猜。
  4. 跑一个真实任务。 发一个小编辑请求，盯着工具调用 —— 路由和能力对不对，一眼见分晓。
bash
# CLI: env-based setup for the OpenAI provider
cat >> ~/.config/goose/config/.env <<'EOF'
OPENAI_HOST=https://daoxe.com/v1
OPENAI_API_KEY=sk-you…-key
EOF
goose

值得注意的坑

工具调用是硬门槛 —— goose 的一切动作都走工具调用，其官方文档明确排除不支持工具调用的模型；选一个真正支持 function calling 的模型。缓存注意：goose 只在 Anthropic、Bedrock、Databricks、OpenRouter、LiteLLM 供应商上自动加 cache_control 标记 —— 在通用的 OpenAI 兼容路径上没有自动缓存，长会话按普通 input 计费。base URL 到 /v1 为止；模型 ID 与账号绑定。更多客户端见客户端设置说明。

验证你拿到的是真模型#

先证明端点可用，再怀疑客户端 —— 这一步失败，改任何设置都没用：

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

一个 OpenAI 形态、却从不打缓存标记的端点，正是该查的那类 —— 先证明连通，再在 temperature 0 下把难题与官方 API 对比：

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

常见问题#

goose 能接 DaoXE 吗？

能 —— goose 的 OpenAI 供应商支持自定义 host：填 https://daoxe.com/v1、你的 key 和准确模型 ID。

为什么会话卡在工具调用上？

所选模型没有可用的 function calling。从 GET /v1/models 里换支持工具的模型。

goose 里用 Claude 有 prompt 缓存吗？

通用路径没有 —— goose 的自动缓存标记只作用于它自己的 Anthropic/Bedrock/OpenRouter/LiteLLM 供应商，不作用于 OpenAI 兼容路径。按普通 input 计费。

多少钱？

按模型、随账号 —— 见实时定价；所有支付方式统一按 1 元 = $1 额度 充值。

试用 DaoXE —— 并亲自 benchmark 它

一个 key 调 GPT、Claude、Gemini、DeepSeek 等。用开源 benchmark 对准我们做对比 —— 别只听我们说。
