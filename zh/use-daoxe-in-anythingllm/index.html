在 AnythingLLM 里用 DaoXE

AnythingLLM 把文档变成可对话的知识库。它的 OpenAI (Generic) 供应商接受任何 OpenAI 兼容端点 —— 一个 DaoXE key 让整个账号目录成为文件 RAG 的后端。

更新于 2026-07-20

AnythingLLM 的 LLM Provider → OpenAI (Generic) 只要 base URL、key 和模型 —— 正是 DaoXE 的形态。配一次，文档聊天、agent、向量流程都从同一个账号取模型（最便宜 API 教程）。

为什么让 AnythingLLM 走 DaoXE#

  • 文档变知识库。 对 PDF 和笔记做 RAG 聊天，模型随选。
  • 一个 key，多家厂商。 换后端不用重新上传或重建索引。
  • token 控制显式化。 上下文窗口和单次 max token 是一级设置，不是隐藏默认。

在 AnythingLLM 里配置#

  1. 打开 LLM 设置。 Settings → AI Providers → LLM → 云供应商里选 OpenAI (Generic)。
  2. 填 Base URL。 填 https://daoxe.com/v1 —— 底层 OpenAI SDK 自己补路径，所以 URL 必须到 /v1 为止。
  3. 加 key、选模型。 粘贴 DaoXE key；Chat Model 字段会列出账号 /v1/models 里的 ID —— 选一个精确的。
  4. 填两个数字字段。 Model context window 填所选模型的真实窗口；Max Tokens 限制单次请求。填错不会报错，只会静默截断。

值得注意的坑

两个数字字段要命：context window 填得比模型真实窗口大，长对话会静默丢失早期历史；填小了浪费模型。面向开发者的选项：AnythingLLM 官方文档自己标注 Generic OpenAI 适合「清楚每个输入含义」的用户 —— 端点不是 OpenAI 形态时才优先考虑官方一方的供应商。精确 ID：从实时模型列表选择；猜的名字在第一条消息就失败。更多客户端见客户端设置说明。

验证你拿到的是真模型#

先证明端点可用，再怀疑客户端 —— 这一步失败，改任何设置都没用：

bash
export DAOXE_API_KEY="your_api_key"

# List the exact model IDs your account can call
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/models \
  -H "Authorization: Bearer ${DAOXE_API_KEY}"

先在客户端之外验证端点，再在 temperature 0 下把难题与官方 API 对比：

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'

常见问题#

AnythingLLM 能接 DaoXE 吗？

能 —— OpenAI (Generic) 供应商：base URL 填 https://daoxe.com/v1，加 key 和精确模型 ID。

为什么长对话忘了开头？

context window 字段填得比模型真实窗口大。改成真实值。

embedding 也能用吗？

AnythingLLM 的 embedding 模型单独配置 —— 在那里从目录选 embedding ID。

怎么收费？

按模型、随账号 —— 实时定价；充值统一 1 元 = $1 额度。

试用 DaoXE —— 并亲自 benchmark 它
