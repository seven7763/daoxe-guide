MiniMax API access — OpenAI-compatible, one key

MiniMax's M-series rides the same OpenAI-compatible base URL as everything else on DaoXE — no separate SDK, no Chinese-console signup dance. One key, catalogue IDs, verifiable.

Updated 2026-07-20

DaoXE fronts MiniMax's M-series through the standard OpenAI shape: POST /v1/chat/completions with a MiniMax model ID; /v1/responses is available on IDs that support it. Existing OpenAI SDK code works unchanged — only the base URL and key change. Where the real cost split comes from: cheapest APIs guide.

Call MiniMax through DaoXE#

Chat path: /v1/chat/completions with Authorization: Bearer. MiniMax reasoning IDs keep thinking out of the answer text only when you ask: extra_body={"reasoning_split": True} puts the chain of thought into reasoning_details.

bash
curl --fail-with-body --show-error --silent \
  https://daoxe.com/v1/chat/completions \
  -H "Authorization: Bearer ${DAOXE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_EXACT_MODEL_ID",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "Say hello in one sentence."}]
  }'
python
# MiniMax reasoning IDs: ask for the thinking split explicitly, or the
# chain of thought arrives fused into the text (or not at all).
from openai import OpenAI

client = OpenAI(base_url="https://daoxe.com/v1", api_key="YOUR_DAOXE_KEY")
r = client.chat.completions.create(
    model="YOUR_EXACT_MODEL_ID",   # a MiniMax-* id from GET /v1/models
    messages=[{"role": "user", "content": "2+2? Think briefly, then answer."}],
    extra_body={"reasoning_split": True},
)
msg = r.choices[0].message
details = getattr(msg, "reasoning_details", None)  # thinking, when split is on
print(details[0]["text"] if details else None)
print(msg.content)                                 # final answer

MiniMax-specific notes#

  • Thinking is opt-in by flag. Without reasoning_split the reasoning may stay fused into the answer text or be dropped entirely — set it if you want a separable chain of thought.
  • Anthropic-shape is also open. MiniMax exposes a Messages-compatible surface; clients that speak Anthropic protocol can use those IDs too — read the catalogue, don't assume.
  • Exact IDs from the live list. M-series versions move (M3 / M2.7 / M2.5 today); copy IDs from GET /v1/models, not from launch posts.

Frequently asked questions#

Do I need a MiniMax console account?

No — MiniMax models ride on your single DaoXE key with normal catalogue IDs from GET /v1/models.

Why is there no separate thinking field?

Set extra_body={"reasoning_split": True}; without it the split isn't guaranteed.

Which endpoints work for MiniMax?

OpenAI-compatible chat (/v1/chat/completions), Responses on supporting IDs, and Anthropic-shape Messages on IDs that declare it.

How much does MiniMax cost here?

Per-model, account-scoped — see live pricing. Top-up is a flat 1 RMB = $1 of credit on every payment method.
